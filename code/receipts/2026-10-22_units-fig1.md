## Method

Script: `2026-10-22_units-fig1.py <bids_root> <git_worktree> <paper.pdf>`, run with Python 3.12,
MNE 1.13.2, MNE-BIDS 0.20.0, NumPy 2.5.4, pandas (Slurm job 13450013). `bids_root` held this commit's
sidecars with the run files linked from the NEMAR copy.

1. Figure: the page-4 content stream is inflated (zlib) and its vector paths (`m`/`l`/`c`) and text positions
   are parsed. The 12 clipped traces are the 6 panels × (x, y). Time comes from the 11 x ticks (labels 0, 2,
   ..., 20 s). µV comes from each axis' y ticks and their labels (0 and ±100 µV, or ±200 µV for c and e).
2. Matching: each panel is compared with all 3750 pairs of its caption class. Each trace vertex is compared
   with the stored sample nearest in time (`round(t * 512)`). For each channel the script computes the Pearson
   r, and the best pair is the one with the highest mean r over x and y. For that pair it reports the
   least-squares slope (figure µV per stored unit), the peak-to-peak ratio (trace / whole stored channel), the
   next-best mean r, and whether the caption's outcomes equal the published outcomes in `scans.tsv`.
3. Reader: for every run the script checks the `.vhdr` fields (`BINARY`, `MULTIPLEXED`, `IEEE_FLOAT_32`, 2
   channels, `Ch1=x,,1,n/a`, `Ch2=y,,1,n/a`). It reads the run with `mne_bids.read_raw_bids` and tests whether
   `get_data()` equals the stored float32 values exactly (scale factor 1). It also records channel types and
   FIFF unit codes.
   In MNE 1.13.2, `read_raw_brainvision` maps unit `n/a` to factor 1 (`_unit_dict["n/a"] = 1`). It applies
   resolution 1 as `cal = 1` and gives the channel type `misc` with `FIFF_UNIT_NONE`. MNE-BIDS 0.20.0
   (`_handle_channels_reading`) copies the `channels.tsv` `units` value into the channel unit code without
   rescaling the data. `µV` maps to `FIFF_UNIT_V`, so with `units = µV` (PR head 4e31f9c8) the unscaled µV
   numbers would be labelled volts. `n/a` is not mapped and leaves `FIFF_UNIT_NONE`.
